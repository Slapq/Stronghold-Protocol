A web remake of Arknights' 卫戍协议：盟约 (auto-chess) mode: Node server + browser client (Preact/htm, Pixi/Spine), the same
rules also run as a Cloudflare Worker with accounts. Upstream chain: sganggs/Stronghold-Protocol → BBleae (晴猫, account-mode
Worker, stronghold.lunar.ag) → this fork (Slapq). Docs are Chinese, code and comments English.

## Facts agents get wrong (top of each brief; most expensive first)

- **Deployment cost (DP) exists in battles**: start 10, +1/s, cap 99; the first deployment is free, every redeploy after a
  knock-out waits for and pays `base.cost`; kits gain DP with `battle.addDp(playerId, n)` (sim-engine.md).
- **No manual skill activation**: the engine auto-casts every skill by its official 技能策略 trigger rule (`skill.trigger.rule`:
  DEFAULT, SKILL_RANGE, TAKE_DAMAGE, SP_FULL, CUSTOM_RANGE, SEARCH …). `skillType` MANUAL only adds the 3 s automatic-operation
  cooldown; trigger rule `MANUAL` (renamed `NEVER`) means "the kit casts it itself". Test harness `makeBattle` sets
  `startOpCooldown: 0` (production 3 s).
- **Kits are keyed by base chess id** (`chess_char_X_YY_a`); elites `_b` share the kit. Skill spec lookup: `kit.skills[id]` →
  `kit.skill` (default skill only) → generic. Talents/trait/install come only from a hand kit (`generic` has `talents: []`).
- **Stat stacking**: ATK% from all sources is summed (`atkPct`), only `*Mul` keys multiply; one buff instance per key.
- **Elite = golden = `_a` → `_b`**; merges use `goldenIdOf`, not `upgradeChessId` (that field is for items).
- **外援 / 甄选 (DIY)**: 87 candidates live only in `data/waiguan.json` (never in chess.json); tier V records are overlays
  of tier VI (9 tier fields; an elite adds its module-level fields: 模组 level 1 at tier V, 3 at tier VI) — always rebuild
  them with `shared/waiguan.js waiguanRecords`; a pick is a pool entry owned by its player (`pool.addOwned`) and only rolls
  when `playerId` is passed.
- **`data/*.json` are generated** (except `tuning.json`): never hand-edit — change the cause, regenerate, commit both. They are
  one-line JSON: diff with `jq -S`. CI has no `.cache/gamedata`, so it cannot catch stale data.
- **Anything bundled into the engines (server/sim, server/match, data, shared) changes the rules version**; a CI/Workers deploy
  fails until it is archived (`npm run deploy:worker` mints it; commit `replay-versions.json` + the new `replay-versions/*.json.gz`).
- **Two runtimes**: the Node server has no `/api` and no accounts; account-mode room create/join need a reservation / an
  approved application; 匹配 exists twice (socket queue on Node, `POST /api/queue` polling + `Matchmaker` DO on the Worker).
- **Client**: no build step (native ES modules, relative imports only, Preact + htm); FX/sounds are keyed by event kind or
  model id, not by skill; layout in rem (1rem = 100 design px at 1080p) with px floors on phones.
- **Assets**: fexli/ArknightsResource has only skin variants of many token models; audio has no mirror; `data/assets.json`
  is one minified line; `tools/fetch-assets-retry.mjs` builds a different (incomplete) plan — use `tools/fetch-assets.mjs`.
- **Node 22 `node --test <directory>` fails**: always pass quoted globs (`node --test 'test/match/*.test.js'`).

## Commands

```sh
npm ci                                   # also vendors client libs into public/vendor
npm start                                # Node server (http://localhost:3000)
npm run test:fast                        # whole suite, MATCH_SEEDS=3 (~7 min on 4 cores)
node --test 'test/sim/*.test.js'         # one area (globs, not directories)
SP_E2E=1 CHROME_PATH=<chrome> node --test test/ui/<name>.e2e.test.js   # browser e2e (not run in CI)
npm run build-data                       # regenerate data/*.json (downloads official tables into .cache/gamedata)
NODE_USE_ENV_PROXY=1 node tools/fetch-assets.mjs   # assets + data/assets.json (behind a proxy; re-run on mirror errors)
npm run build:worker                     # Worker build (dist/), resource pack; deploy only via npm run deploy:worker
node tools/doc-index.mjs                 # regenerate docs/context/DOC-INDEX.md after editing any docs/*.md
node tools/kit-coverage.mjs --missing    # which selectable skills lack a hand-authored kit
```

## Working rules

- Verify before you state: cite `file:line`, run a test or a sandbox for behaviour claims, mark the rest UNVERIFIED. Unit tests
  that call a helper directly (e.g. `pool.roll` with `playerId`) do not prove the real call site does the same.
- After editing docs: regenerate the index (`test/doc-index.test.js` fails otherwise) and run `node --test test/docs-consistency.test.js`
  (it pins wording in DATA.md, build-data.mjs and client modules).
- Keep briefs current: when you change a fact a brief states, update the brief in the same commit.
- Commits in this fork: author `Slapq <106904191+Slapq@users.noreply.github.com>`, Chinese commit messages, no AI attribution
  (no Co-Authored-By / Claude-Session lines; no Claude footer in PR bodies). Never force-push others' branches; never run
  `wrangler deploy` / `wrangler login` from an agent.
